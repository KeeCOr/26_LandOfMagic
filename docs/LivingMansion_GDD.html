1. 문제 정의 / 페르소나 / 코어 루프

  • 문제: Godot 기반 저택 시뮬레이션/생활형 게임으로 추정되나, 정확한 장르와 타겟 문제는 확인 필요.
  • 페르소나: 시뮬레이션·생활형 게임을 즐기는 캐주얼~미드코어 플레이어 (제안, 확인 필요).
  • 코어 루프(제안): 저택 탐색 → 자원/공간 관리 → 이벤트 발생 → 결과 반영 → 다음 루프. 실제 씬/스크립트 로직 기반 검증 필요.

2. MVP / KPI / 참고 단계 및 교훈

  • MVP 범위: scenes, resources, scripts, tests 디렉터리 존재 확인됨. 실제 플레이 가능한 최소 루프 범위는 확인 필요.
  • KPI: 수치 데이터 없음 — 확인 필요 (세션 길이, 리텐션 등 임의 수치 생성 금지).
  • 참고 단계: 테스트 코드 존재 → 최소한의 QA 체계는 갖춰져 있음(확인 필요, 커버리지 불명).
  • 교훈(제안): 콘텐츠 총량이 불명확한 상태로 프로토타입을 확장하면 스코프 관리가 어려워짐 — 콘텐츠 인벤토리 문서화 우선 제안.

4. 확인된 사실 / 미확인 사항

  • 확인됨: Godot 엔진 프로젝트, scenes/resources/scripts/tests 폴더 존재.
  • 미확인(확인 필요): 프로젝트 버전, 정확한 장르, 콘텐츠 총량(씬 수, 아이템 수 등), 코어 루프 세부 규칙.

5. 페이싱 / 재미 사슬 / 예시 2개 / 피로도 / 경제 / 온보딩

  • 페이싱(제안): 탐색-관리-이벤트 순환 주기를 짧게 유지해 세션 진입 장벽 낮추기.
  • 재미 사슬(제안): 호기심(탐색) → 통제감(관리) → 놀라움(이벤트) → 성취(해결).
  • 예시 1(제안): 방 하나를 정리하면 숨겨진 아이템 발견 → 다음 방 탐색 동기 부여.
  • 예시 2(제안): 자원 부족 상황에서 선택지 이벤트 발생 → 트레이드오프 결정.
  • 피로도(제안): 반복 이벤트 패턴 방지를 위한 이벤트 풀 로테이션 필요, 실제 구현 여부 확인 필요.
  • 경제(확인 필요): 재화/자원 시스템 존재 여부 및 밸런스 수치 불명.
  • 온보딩(제안): 첫 세션에 저택 구조와 핵심 조작만 노출, 나머지는 점진적 공개.

6. HUD 5가지 상태 / 접근성 / AV

  • HUD 상태(제안, 확인 필요): 기본(Idle) / 상호작용 가능(Interactable) / 경고(Warning) / 진행중(Processing) / 완료(Complete).
  • 접근성: 색맹 대응 팔레트, 텍스트 크기 조절, 키보드/컨트롤러 대체 입력 — 구현 여부 확인 필요.
  • AV (오디오/비주얼):
    • 구현됨: 확인 필요 (scenes/resources 존재로 기초 에셋은 있음).
    • 계획됨: 확인 필요.
    • 제안: 저택 분위기를 강화하는 앰비언트 사운드 레이어링.

7. 우선순위 3가지

  1. 프로젝트 버전 및 콘텐츠 인벤토리(씬/스크립트/리소스 목록) 확정 — 확인 필요 항목 해소.
  2. 코어 루프 실증 플레이테스트로 재미 사슬 검증.
  3. 테스트 커버리지 확인 및 QA 체계 문서화.

구성요소

역할 선택 입력→판정→피드백 상태
씬(scenes) 씬 전환 선택 여부 미검증 씬 로드 입력 → 전환 조건 판정 → 화면 전환 피드백 구현됨(Godot 기반)
리소스(resources) 리소스 종류 선택 미검증 리소스 참조 입력 → 유효성 판정 → 로드 결과 피드백 구현됨
스크립트(scripts) 해당 없음 게임 로직 입력 → 스크립트 판정 → 동작 피드백 구현됨
테스트(tests) 해당 없음 테스트 실행 입력 → 통과/실패 판정 → 결과 리포트 피드백 구현됨
